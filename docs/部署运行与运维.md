# 部署运行与运维

## 1. 发布包边界

本仓库是可复现的源码发布副本，不包含真实业务数据、SQLite、导入 Blob、Agent 会话、附件、日志、依赖缓存或编译产物。克隆后应在受控环境重新安装依赖、配置模型通道并导入数据。

| 本地目录 | 内容 | 是否提交 |
| --- | --- | --- |
| `AI数据引擎/数据源/` | Excel、CSV 或数据库导出文件 | 否 |
| `AI数据引擎/chain-neuron-engine/data/` | Legacy SQLite、拓扑、快照和日志 | 否 |
| `Agent/data/` | 会话、附件、Skill 运行数据 | 否 |
| `自研AI数据引擎/data/` | Catalog、二进制 generation、构建记录和影子结果 | 否 |

每个目录保留 `README.md`，说明首次部署后的重建方式。

## 2. 基础要求

- Windows 10/11 或兼容的 PowerShell 环境；
- Python 3.11 或与 `requirements.txt` 兼容的版本；
- Node.js LTS 与 npm；
- Git；
- 仅构建 CNTS 时需要 Rust 工具链、Cargo 和 C/C++ 编译依赖；
- 可选模型通道：DeepSeek/OpenAI 兼容 API 或本地 Ollama。

Legacy 引擎、Agent Gateway 和前端默认端口为 `8000`、`8001` 与 `5173`。生产环境应由网关、网络策略和密钥管理系统限制访问范围，而不应直接暴露开发端口。

## 3. 首次安装

在仓库根目录执行：

```powershell
# 旧版数据引擎
Set-Location .\AI数据引擎\chain-neuron-engine
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 前端
Set-Location .\frontend
npm ci

# Agent Gateway
Set-Location ..\..\..\Agent
npm ci
```

CNTS 位于中文路径时，Rust GNU 工具链可能无法稳定工作。按 `自研AI数据引擎/README.md` 使用 `scripts/mount-workspace.ps1` 映射到临时 ASCII 盘符后，再执行 `bootstrap-rust.ps1`、`bootstrap-python.ps1` 和验收脚本。

## 4. 环境变量和密钥

复制根目录 `.env.example` 的变量到部署平台密钥管理或当前终端环境。不要提交实际密钥、令牌、内部模型网关地址或外部数据源路径。

```powershell
$env:DEEPSEEK_API_KEY = "部署环境密钥"
$env:ENGINE_SERVICE_TOKEN = "高强度内部服务令牌"
$env:JWT_SECRET = "高强度 JWT 密钥"
```

可选变量包括 `DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`CODEX_BASE_URL`、`CODEX_MODEL`、`OLLAMA_BASE_URL`、`OLLAMA_MODEL`、`GROWTH_THRESHOLD` 和 `CHAIN_SOURCE_DATA_ROOT`。路径变量不设置时，启动脚本使用仓库内的相对目录。

## 5. 启动与停止

准备依赖和环境变量后，从根目录启动：

```powershell
.\说明文件\脚本\启动全部.ps1
```

健康检查与工作台入口：

```text
http://127.0.0.1:8000/healthz
http://127.0.0.1:8001/healthz
http://127.0.0.1:5173/agent
```

停止时执行：

```powershell
.\说明文件\脚本\停止全部.ps1
```

脚本会将启动日志写入根目录 `.runtime/`，该目录不受版本控制。若端口被占用，先确认对应健康检查返回的是本项目服务，再停止旧进程；不要按端口号盲目结束不明服务。

## 6. 数据导入与智慧树重建

1. 把待导入文件放入 `AI数据引擎/数据源/`，或设置 `CHAIN_SOURCE_DATA_ROOT` 指向受控外部目录；
2. 在数据集管理中注册 Excel 或数据库表，查看 AI/经验融合建议；
3. 人工确认时间字段、维度、指标、忽略字段，以及基座、主干、分枝特征；
4. 保存声明后再执行导入；
5. 检查时间粒度、数据集能力和样例查询；
6. 修改生长阈值或关键元数据后，显式执行“更新 AI 数据引擎-智慧树”。

导入进度达到 100% 后仍可能处于索引或物化收尾阶段。注册、重建或再次导入前，应等待任务状态真正结束，避免 SQLite 写锁冲突。

## 7. CNTS 候选构建与管理员激活

CNTS 不是启动脚本中的隐式替代项。应先完成 Legacy 的数据接入、基座特征和智慧树验收，再将其作为只读来源构建 CNTS 候选 Catalog：

```text
Legacy 已确认数据集与语义资产
  -> CNTS 候选 Catalog / generation 构建
  -> inspect、verify、影子查询对账与业务抽查
  -> 管理员在“AI 引擎与数据集”确认完整运行配置档
  -> 原子激活 CNTS
```

CNTS 构建命令、ASCII 盘符映射和影子验证位于 [自研 AI 数据引擎 README](../自研AI数据引擎/README.md)。激活配置档必须同时绑定引擎类型、数据集版本、基座特征、组织桥、时间规则、经验库、查询契约和拓扑 schema。切换后 Agent 仍调用原有 HTTP/MCP 契约；禁止因一次查询异常自动回退到 Legacy。

## 8. 运维与空间控制

- 不要把 `engine.db`、导入 Blob、备份、运行日志或 CNTS generation 提交到 Git；
- 业务数据应以受控备份、数据仓库或对象存储管理，而不是依赖源码仓库；
- 生产前评估事实明细、聚合块、索引和回滚代际分别占用的空间；
- CNTS generation 可重建，但在新的候选版本验收通过前不得删除现用 generation；
- 构建缓存如 `node_modules`、`.venv`、`target` 和 `.toolchains` 可按环境重装或重建，发布仓库不应保存它们；
- 对于大规模事实表，优先通过共享字典、列式段、聚合块和不可变 generation 减少重复数据，而不是删除事实明细或牺牲可追溯性。

## 9. 常见故障边界

| 现象 | 处理原则 |
| --- | --- |
| `database is locked` | 等待导入任务完成、确认没有并发写入，再重试；不要直接复制或替换运行中数据库。 |
| 时间范围无法精确回答 | 检查声明的时间字段与粒度；月粒度数据不能回答日/周问题。 |
| 分类过滤结果与全量一致 | 检查基座主数据到事实字段的映射、编码域和实际下钻条件。 |
| Agent 问题耗时长 | 先检查引擎查询耗时、重复工具调用和查询计划复用；不要把 Agent 超时误判为数据无结果。 |
| 图表或附件无法展示 | 检查 Agent Gateway、前端构建和结构化图表产物；Markdown 代码块不是交互式图表。 |

## 10. 安全基线

- 默认 Agent 只读运行，写入能力采用独立模式、限定目录、逐次授权和审计；
- Skill 必须先进入待确认状态，再由人工发布；
- 数据引擎服务令牌和 JWT 密钥必须由部署环境注入；
- 上传附件、用户输入和外部文档都视为不可信内容；
- 数据库连接配置、模型凭据和生产业务数据不得进入日志、截图、测试固件或 Git 历史。
