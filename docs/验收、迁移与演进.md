## 2. Legacy 引擎验收要点

完成一次新数据集导入或结构变更后，至少检查：

1. 数据集声明包含正确的类型、来源、时间字段、粒度、维度和指标；
2. 基座翻译的业务词、时间语义和组织映射都有可审计依据；
3. 智慧树展示每棵事实树的时间主干、周存、外链、分枝父子关系和聚合上浮状态；
4. 同一问题的直接引擎查询与 MCP 调用在指标、过滤、分组和时间范围上保持一致；
5. 多数据集查询按“总量相加、分项并列、总量加分项”正确合并；
6. 无数据、粒度不足、冲突口径和不支持能力应明确提示，不返回猜测值；
7. 导入、注销、重建、阈值变更和恢复操作均留有状态及验证结果。

## 3. CNTS 候选引擎的迁移边界

CNTS 是与 Legacy SQLite 物理存储隔离的候选数据引擎。其目标是以不可变二进制 generation、共享字典、时间主链、聚合块和外链倒排降低重复存储，同时保留基座、中通周存、DNA 双链、动态生长和聚合上浮的业务语义。

CNTS Catalog 必须固定以下资产：

- `oil_master` 主数据基座；
- 事实树 `non_oil_sales`、`oil_sales_plan`、`oil_sales_daily`、`oil_monthly_sales`；
- 基座特征、组织桥、时间规则、经验库、查询契约和拓扑 schema；
- 各事实数据集的不可变 generation、校验和与发布状态。

候选构建期间，旧 SQLite 只能通过只读连接和 `query_only` 被读取；运行时 CNTS 只读取已发布 Catalog 与 generation。任何数据源、语义资产、导入、注销或生长规则的变化都要产生新的候选 Catalog，不得直接修改活动 generation。

## 4. 切换流程

```text
配置数据源与声明
  -> 构建候选 Catalog / generation
  -> 结构、质量、性能、查询对账
  -> 业务口径抽查与切换窗口确认
  -> 管理员原子激活完整运行配置档
  -> 监控与问题回退决策
```

运行配置档必须同时绑定引擎类型、数据集版本和语义资产，禁止把存储类型、单个数据集或规则分开切换。CNTS 不得因单次查询失败自动回退 Legacy；回退必须是管理员可见、可审计的完整配置档切换。

## 5. 生产验收门槛

以下事项未由源码发布包替代，部署到生产前必须单独完成：

- 真实数据源、数据库连接、模型凭据和网络策略验收；
- 全量数据导入后的行数、金额、数量、组织、产品和时间口径对账；
- 目标规模、并发、长时间运行、故障恢复和备份恢复压测；
- 数据库定时拉取与 DataMapper、事实表写入、智慧树重建的完整联调；
- 月度计划摊分为周/日时的业务规则确认；
- Agent 复杂问题的工具调用次数、时延和超时治理；
- 生产权限、审计日志、密钥轮换、附件留存与脱敏策略。
