# 产品架构与数据治理

## 1. 产品定位

链式多维时空 AI 数据引擎面向需要按业务口径查询、汇总和解释结构化数据的场景。它把自然语言理解、业务语义、数据集能力和精确聚合分开处理：模型负责理解问题和组织结果，数据引擎负责把问题转换为可验证的标准参数并返回可信数据。

系统由三个可独立演进的部分组成：

| 部分 | 职责 | 不负责的事 |
| --- | --- | --- |
| AI 数据引擎 | 数据集注册、基座语义、智慧树、精确聚合、查询契约和审计 | 对话规划、模型推理 |
| Agent Gateway | 会话、附件、模型通道、Skill、MCP 调用、图表和结果解释 | 直读业务库或绕过引擎计算 |
| CNTS 自研引擎 | 不可变二进制数据集、Catalog、只读查询适配和候选构建 | 自动替换已启用引擎 |

```text
用户 / Agent
  -> Agent Gateway / 可选 Skill
  -> HTTP 或 MCP 查询契约
  -> 基座问题分解与语义翻译
  -> 中通内链定位 -> 中通周存聚合 -> DNA 外链与分枝下钻
  -> 各数据集结果
  -> 按问题口径合并
  -> 一个统一输出
```

Agent 与数据引擎通过通道契约协作，而非写死到某个模型或 Harness。没有匹配 Skill 时，Agent 仍可基于引擎能力发现和统一查询契约完成通用查询。

## 2. 基座：问题分解规范器

基座不是事实表字段的副本，也不承载业务时间序列。它承担查询前的过滤、翻译、赋能、归一化和纠偏，把人类表述编译为智慧树可执行的标准参数。

典型能力包括：

- 将“上周”“2026 年一季度”“春节”等时间语义翻译为可审计的日期范围或时间规则；
- 将“类别甲”“类别乙”等业务名称映射到已确认的产品主数据、类别或编码集合；
- 将组织名称映射到组织层级一、组织层级二、组织层级三、定位单元等规范组织条件；
- 识别同比、环比、完成率等派生指标所需的对比期间和计算规则；
- 根据数据集能力决定哪些数据集参与查询，并在粒度不够时明确拒答而不是伪造精度。

基座特征、时间规则和 AI/经验库建议都必须经过人工确认后启用。AI 可以提出候选字段、映射和规则，但不能静默改变已启用的业务口径。

## 3. 智慧树与数据拓扑

所有事实数据集共享一个语义基座；每个事实数据集在其上形成一棵独立智慧树。维表/主数据为基座提供翻译能力，不被误作事实树。

可观看 [智慧树查询原理动画](../演示动画/预览/智慧树查询原理.mp4)。它使用模拟拓扑展示入口、统一基座、独立智慧树、侧向分枝、数据集结果与统一输出的关系，不包含真实业务数据；完整分镜和可复现源码位于 [演示动画](../演示动画/README.md)。

### 3.1 三层物理空间

每棵树按时间纵向堆叠，横截面由三个同心层组成：

1. **中通内链**：中心实心柱，保存时间及跨数据集共有特征的定位索引。
2. **中通周存**：中间圆环，保存经过物化的聚合数据块，用于快速读取。
3. **DNA 外链**：最外圆环，保存非共有特征、倒排关系和可继续下钻的分枝入口。

DNA 双链描述的是数据链物理拓扑，不是额外查询层级。稳定查询路径始终是：**中通内链进 -> 中通周存过 -> DNA 外链出**。

### 3.2 时间堆叠与生长

时间是主堆叠轴，但不是唯一共有特征。每个时间层先依据已声明的粒度建立主干；当层内数据量超过系统阈值时，按照已确认的元数据优先级递归生长分枝，例如：

```text
时间层
  -> 组织层级一
    -> 组织层级二
      -> 组织层级三
        -> 定位单元
          -> 产品类别
```

每个可见分枝节点必须保留父节点、分枝维度、深度和物化聚合结果。这样查询“某日各组织层级一业务”可直接读取首层分枝；查询“示例区域甲组织层级一某类产品”再沿该分枝继续下钻。前端结构总览必须把完整父子关系画成侧向生长的枝，而不是孤立方块。

生长阈值改变后，不会自动改写历史拓扑。管理员需要显式执行“更新 AI 数据引擎-智慧树”，以当前阈值和确认后的元数据重新计算结构。

## 4. 数据接入与字段治理

数据集管理是唯一接入入口，支持 Excel 注册和数据库表注册。注册与导入分离：先解析样本、生成字段建议、由用户确认角色和特征，再保存声明并执行导入。

| 阶段 | 责任 | 结果 |
| --- | --- | --- |
| 注册 | 选择 Excel 或数据库表，填写数据集基本信息 | 待确认数据集声明 |
| AI/规则分析 | 结合字段统计、经验 YAML 和数据类型提出候选 | 可编辑建议与理由 |
| 人工确认 | 指定时间、维度、指标、忽略字段及基座/主干/分枝特征 | 已确认声明 |
| 导入与构建 | 写入事实或主数据、生成聚合和智慧树拓扑 | 可查询数据集 |
| 验收 | 检查行数、时间粒度、能力、分枝和查询样例 | 可发布或待修正 |

数据集只有两类：`通用事实` 与 `维表/主数据`；来源只有 `基座数据` 与 `界面注册`。数据库定时拉取不是当前发布范围，不能被误表述为已实现能力。

## 5. 查询、合并与精度

引擎接收结构化查询计划，包括数据集、标准时间范围、过滤条件、指标、分组维度和比较规则。`group_by` 是有序数组；多维分组和“下层过滤、上层分组”必须由事实数据精确聚合，不能用首个节点或近似周存替代。

多数据集结果先独立计算，再根据用户意图合并：

- **总量问题**：在口径可比且确认允许时相加；
- **分项问题**：并列展示，不强行相加；
- **总量加分项**：同时返回总量和各数据集分项；
- **无命中**：保留参与范围说明，按问题规则显示 `0` 或跳过，不能把无数据伪装为未参与查询。

金额与数量使用 Decimal 或定点口径聚合。月粒度计划不能被伪装为精确周计划；没有经确认的摊分规则时，系统应披露粒度不足。

## 6. Agent、图表与附件

Agent 通过只读 MCP/HTTP 调用引擎，不直接读取 SQLite、Excel 或 CNTS 二进制段。它负责会话、模型执行、结构化回答、表格、ECharts 图表和 PNG 导出。

图片、PDF、Word 与 Excel 附件仅在授权会话范围内处理；Excel 不执行公式。默认 Agent 运行环境保持只读，以避免不可信附件或提示注入获得写入权限。Skill 的生成、修改、发布和停用经由受控 SkillStore，AI 只能生成待人工确认的草稿。

## 7. 存储与引擎切换

当前发布包同时包含 Legacy SQLite 引擎和 CNTS 候选实现。CNTS 使用不可变 generation 和多数据集 Catalog 固定以下运行资产：存储适配器、数据集版本、基座特征、组织桥、时间规则、经验库、查询契约和拓扑 schema。

切换必须以完整运行配置档为原子单位：构建候选 -> 校验 -> 业务抽查 -> 管理员确认 -> 原子激活。系统不得在 CNTS 查询异常时偷偷回退 Legacy，也不得在活动 CNTS Catalog 上直接导入、注销、重建或修改语义资产；这些变更必须生成新的候选 Catalog 后重新验收。

向量数据库只适合文本资料、规则说明和知识检索的语义召回，不能替代数值事实、精确过滤、时间比较或智慧树物理拓扑。
